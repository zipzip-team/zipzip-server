# Zipzip 용어 표준화

## 1. 문서 목적

이 문서는 Zipzip 서버 데이터 모델링에 앞서 업무 용어를 표준화하기 위한 문서이다.
Figma 화면, 제품 플로우, 서버 저장 범위를 기준으로 용어의 의미와 경계를 정의한다.

이 문서에서 확정한 용어는 이후 한글-영어 매핑, 데이터 표준화, ERD, API 명세, 데이터 사전 작성의 기준으로 사용한다.

## 2. 핵심 도메인 구조

```text
공유 뷰
└── 공유 폴더
    └── 앨범
        └── 사진
```

- 공유 뷰는 하단 네비게이션의 `공유` 탭에 해당하는 최상위 뷰이며 DB 엔티티가 아니다.
- 공유 폴더는 공유 뷰에 여러 개 표시되는 실제 공유 공간이다.
- 공유 폴더에는 방장과 멤버가 있고 초대 코드, 관리 화면, 채팅방이 속한다.
- 앨범은 공유 폴더 안에서 참여자들이 사진을 묶는 단위이다.
- 사진은 앨범에 속한 실제 이미지 파일이다.

## 3. 용어 표준화 표

| 구분 | 표준 용어 | 사용하지 않을 용어/혼용어 | 정의 | 서버 저장 여부 | 비고 |
|---|---|---|---|---|---|
| 사람 | 사용자 | 회원, 유저, 계정 | Apple 로그인 후 서버에 등록된 사람 | O | 로그인 전에는 서버와 상호작용하지 않는다. |
| 화면 | 공유 뷰 | 공유 폴더 엔티티, 공유 탭 엔티티 | 사용자가 참여 중인 여러 공유 폴더를 보는 최상위 화면 | X | 하단 네비게이션의 공유 탭을 의미한다. |
| 공유 공간 | 공유 폴더 | 방, 공유방, 앨범 | 여러 사용자가 초대 코드로 참여해 사진과 채팅을 공유하는 공간 | O | 방장과 멤버, 초대 코드, 채팅방이 존재한다. |
| 사진 묶음 | 앨범 | 폴더, 모음 | 공유 폴더 안에서 사진들을 묶는 하위 단위 | O | 물리 테이블명은 로컬 앨범과 구분하기 위해 `shared_album`을 사용한다. 방장과 멤버 모두 생성할 수 있고 생성자만 수정·삭제할 수 있다. |
| 미디어 | 사진 | 이미지, 포토 | 앨범 안에 포함되는 실제 사진 파일 | O | 공유 폴더 플로우에서만 서버에 업로드하며 업로더만 수정·삭제할 수 있다. 이미지 파일은 Object Storage에 저장한다. |
| 사진 반응 | 사진 좋아요 | 좋아요, 반응 | 사용자가 특정 사진에 좋아요를 누른 상태 | O | 사진별 좋아요 수와 내 좋아요 여부를 표현한다. |
| 사진 댓글 | 사진 댓글 | 이미지 댓글 | 단일 사진에 달리는 댓글 | O | 공유 폴더 채팅과 별도 개념이며 작성자만 수정·삭제할 수 있다. |
| 채팅 | 채팅방 | 공유 폴더 채팅방 | 공유 폴더 방장과 멤버가 대화하는 공간 | O | 공유 폴더에 종속된다. |
| 채팅 | 채팅 메시지 | 채팅, 메시지 | 채팅방 안에서 사용자가 작성한 메시지 | O | 사진 댓글과 별도 개념이며 작성자만 수정·삭제할 수 있다. |
| 역할 | 방장 | 생성자, 소유자 | 공유 폴더를 만든 사용자 | O | 공유 폴더 삭제 권한을 가진다. |
| 역할 | 멤버 | 참여자, 초대받은 사람 | 초대 코드로 공유 폴더에 참여한 사용자 | O | 공유 폴더 삭제 권한은 없으며 직접 나간 뒤 초대 코드로 재참여할 수 있다. |
| 초대 | 초대 코드 | 참여 코드, 방 코드 | 공유 폴더 참여에 사용하는 고정 코드 | O | 만료·재발급·재사용되지 않는다. |
| 초대 | 초대 코드 예약 원장 | 초대 이력 | 발급한 초대 코드의 영구 비재사용을 보장하는 서버 내부 원장 | O | 공유 폴더 물리 삭제 후에도 삭제하지 않는다. 사용자에게 노출하는 업무 개념은 아니다. |
| 로컬 개념 | 개인 앨범 | 로컬 앨범 | 서버와 무관하게 기기 안에서만 동작하는 개인 앨범 | X | 공유하려면 사용자가 명시적으로 업로드해야 한다. 자동 병합은 없다. |
| 기기 | 기기 | 디바이스 | 사용자에게 표시되는 촬영 기기 또는 앱 설치 기기 태그 | O | 사용자 단위로 저장하고 `CAMERA`, `APP_DEVICE` 유형을 구분한다. |

## 4. 서버 저장 범위

### 4.1 서버에 저장하는 대상

- 사용자
- 공유 폴더
- 공유 폴더 멤버십
- 앨범
- 사진
- 사진 좋아요
- 사진 댓글
- 채팅방
- 채팅 메시지
- 초대 코드
- 초대 코드 예약 원장
- 공유 폴더 권한/역할
- 기기 태그와 기기 유형

### 4.2 서버에 저장하지 않는 대상

- 하단 네비게이션의 공유 뷰 자체
- 로그인 전 사용자의 활동
- 개인 앨범
- 로컬 기기 내 사진 정리 정보
- 공유 폴더 플로우와 무관한 완전 삭제 처리

## 5. 확정된 결정

- 서버 기준 사람 단위는 `사용자`로 부른다.
- `공유 뷰`는 UI 영역이며 DB 엔티티로 만들지 않는다.
- 공유 뷰는 현재 사용자가 참여 중인 여러 `공유 폴더`를 보여준다.
- `공유 폴더`는 서버에 저장되는 실제 공유 공간이다.
- 공유 폴더를 만든 사람은 `방장`이고 초대받은 사람은 `멤버`이다.
- 공유 폴더 안에는 여러 개의 `앨범`이 존재할 수 있다.
- 앨범은 방장과 멤버 모두 생성할 수 있다.
- 앨범 이름 수정과 앨범 삭제는 해당 앨범을 생성한 사용자만 할 수 있다.
- 사진이 없는 앨범도 존재할 수 있다.
- 앨범 안에는 여러 개의 `사진`이 존재할 수 있다.
- 공유 폴더 플로우에서만 서버에 사진을 업로드한다.
- 사진은 이미지 파일만 Object Storage에 저장하며, EXIF 원본이나 촬영 위치 같은 상세 사진 메타데이터는 저장하지 않는다.
- 날짜별 그룹 표시를 위한 최소 촬영일시는 nullable 업무 필드로 저장하고, 없으면 생성 시각을 표시·정렬 기준으로 사용한다.
- 공유 폴더 멤버별 기기 태그 표시에 필요한 기기명은 사용자 단위로 서버에 저장한다.
- 기기 태그는 촬영 기기 `CAMERA`와 앱 설치 기기 `APP_DEVICE`로 구분한다.
- 사진 좋아요는 사진별 단순 좋아요로 저장하며 이모지 반응 타입은 두지 않는다.
- 사진은 해당 사진 업로더만 수정·삭제할 수 있다.
- 사진 댓글은 단일 사진에 종속되며 해당 댓글 작성자만 수정·삭제할 수 있다.
- 공유 폴더 채팅방은 공유 폴더 방장과 멤버 간의 대화 공간이며 공유 폴더 생성 시 자동 생성한다.
- 공유 폴더 채팅 메시지는 사진 댓글과 분리해서 저장하며 해당 메시지 작성자만 수정·삭제할 수 있다.
- 날짜별 사진 그룹은 촬영일 기준으로 표시한다.
- 공유 폴더와 앨범의 사진 수는 집계 컬럼 없이 실시간 count로 계산하는 것을 1차 기준으로 한다.
- 로그인 전에는 서버와 상호작용하지 않는다.
- 로그인 전에 만든 개인 앨범은 Apple 로그인 후에도 자동 병합하지 않는다.
- 로그인 후 사용자가 개인 앨범을 공유하고 싶을 때 명시적으로 공유 폴더의 앨범에 업로드할 수 있다.
- 초대 코드는 공유 폴더에 속하며 만료되거나 재발급되지 않는다. 발급 코드는 예약 원장에 영구 보존해 삭제된 공유 폴더의 코드도 재사용하지 않는다.
- 공유 폴더 이름은 방장과 멤버 모두 수정할 수 있다.
- 공유 폴더 삭제 권한은 방장에게만 있고 멤버는 삭제할 수 없다.
- 방장과 다른 멤버는 특정 멤버를 강제로 퇴장시킬 수 없다.
- 멤버는 공유 폴더에서 직접 나갈 수 있고 유효한 초대 코드로 다시 참여할 수 있다.
- 방장이 삭제한 공유 폴더는 사용자에게 복구 기능을 제공하지 않는다.
- 개별 삭제한 사진·앨범과 삭제된 공유 폴더 데이터는 30일 뒤 물리 삭제한다.
- 초대 코드 예약 원장은 공유 폴더 물리 삭제 후에도 영구 보존한다.
- Zipzip 서비스 사용자가 탈퇴한 뒤 동일한 Apple 계정으로 재가입하면 기존 사용자 정보를 복구한다.
- 사용자 탈퇴 시 방장으로 만든 공유 폴더와 멤버로 참여 중인 멤버십을 soft delete한다.
- 사용자 정보를 복구해도 과거 공유 폴더 멤버십은 자동으로 복구하지 않는다.

## 6. 현재 기준 관계 요약

```text
사용자
├── 기기
└── 공유 폴더 멤버십
    ├── 방장
    └── 멤버

공유 폴더
├── 채팅방
│   └── 채팅 메시지
└── 앨범
    └── 사진
        ├── 사진 좋아요
        └── 사진 댓글
```
