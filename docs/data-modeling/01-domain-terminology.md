# Zipzip 도메인 용어

## 1. 문서 목적

이 문서는 Zipzip 서버 데이터 모델링과 API 설계에서 사용할 한글 업무 용어를 정의한다.
이후 영어명, DB 테이블명, API 경로, 권한 정책은 이 문서의 용어를 기준으로 맞춘다.

## 2. 최종 공유 계층

```text
공유 탭
└── 공유 그룹
    ├── 공유 그룹 멤버십
    ├── 그룹 채팅 메시지
    └── 공유집(앨범)
        └── 사진
            ├── 사진 좋아요
            └── 사진 댓글
```

- 공유 탭은 하단 네비게이션 화면이며 서버 테이블로 만들지 않는다.
- 공유 그룹은 초대 코드와 멤버십을 가지는 최상위 공유 공간이다.
- 공유집(앨범)은 공유 그룹 안에서 사진을 담는 단위이다.
- 사진은 공유집(앨범)에 업로드된 실제 이미지 파일 원본이다.
- 사진 좋아요와 사진 댓글은 단일 사진에 종속된다.
- 그룹 채팅 메시지는 사진 컨텍스트 없이 공유 그룹 안에서 작성하는 일반 메시지이다.

## 3. 핵심 용어

| 구분 | 한글 용어 | 정의 | 서버 저장 | 비고 |
|---|---|---|---|---|
| 사람 | 사용자 | Apple 로그인 후 서버에 등록된 사람 | O | 콘텐츠 작성자, 생성자, 업로더의 기준 |
| 화면 | 공유 탭 | 여러 공유 그룹을 보여주는 하단 네비게이션 화면 | X | UI 개념 |
| 화면 | 사진집 | 로컬 중심 사진 묶음 화면 | X | 서버 자동 동기화 대상 아님 |
| 공유 공간 | 공유 그룹 | 초대 코드와 참여자가 있는 최상위 공유 공간 | O | `shared_group` |
| 관계 | 공유 그룹 멤버십 | 사용자와 공유 그룹 사이의 참여 관계 | O | `HOST`, `MEMBER` 역할 보유 |
| 공유 공간 | 공유집(앨범) | 공유 그룹 안에서 사진을 담는 하위 공간 | O | `shared_album`으로 저장 |
| 관계 | 앨범-사진 매핑 | 사진과 공유집(앨범)의 N:M 소속 관계 | O | `shared_album_photo`로 저장 |
| 미디어 | 사진 | 공유 그룹 안에서 업로드되는 실제 사진 파일 원본 | O | 공유 그룹에 직접 속하지 않고 `shared_album_photo`로 공유집(앨범)에만 소속 |
| 사진 반응 | 사진 좋아요 | 사용자가 특정 사진에 좋아요를 누른 상태 | O | 취소 시 물리 삭제 |
| 사진 댓글 | 사진 댓글 | 단일 사진에 달리는 댓글 | O | MVP는 작성·조회만 제공 |
| 채팅 | 그룹 채팅 메시지 | 공유 그룹 안에서 작성하는 일반 채팅 메시지 | O | 사진 댓글과 별도 |
| 사진 메타데이터 | 촬영 기기명 | iOS가 EXIF에서 추출한 사진별 촬영 기기명 | O | `photo.device_model` nullable 문자열 |

## 4. 공유 그룹

- 공유 그룹은 초대 코드로 참여하는 최상위 공유 공간이다.
- 공유 그룹은 방장(`HOST`) 1명과 멤버(`MEMBER`) 여러 명을 가질 수 있다.
- 공유 그룹 이름 수정과 공유 그룹 삭제는 방장만 할 수 있다.
- 멤버 강제 퇴장은 제공하지 않는다.
- 멤버가 직접 나가면 멤버십을 물리 삭제한다.
- 활성 멤버십은 멤버십 행이 존재하고 상위 공유 그룹과 사용자가 모두 soft delete되지 않은 상태이다.
- 나간 사용자는 유효한 초대 코드로 다시 참여할 수 있다.
- 공유 그룹 안에는 여러 공유집(앨범)이 존재할 수 있다.
- 공유 그룹 안에는 그룹 채팅 메시지가 존재할 수 있다.

## 5. 공유집(앨범)

- 공유집(앨범)은 공유 그룹 안에서 사진을 담는 하위 공간이다.
- 물리 테이블명은 `shared_album`을 사용한다.
- 별도 `shared_house` 테이블은 두지 않는다.
- 공유집(앨범)은 활성 공유 그룹 멤버가 생성할 수 있다.
- 공유집(앨범) 이름 같은 정보 수정은 활성 공유 그룹 멤버가 할 수 있다.
- 공유집(앨범) 삭제는 해당 공유집(앨범) 생성자 또는 탈퇴한 생성자의 공유 그룹 방장이 할 수 있다.
- 공유집(앨범) 삭제 시 해당 앨범-사진 매핑은 즉시 물리 삭제한다. 다른 공유집(앨범)에도 속한 사진은 원본이 유지되지만, 그 공유집(앨범)이 마지막 소속이었던 사진은 원본도 함께 soft delete된다.
- 사진이 없는 공유집(앨범)도 존재할 수 있다.

## 6. 사진

- 사진은 공유 그룹 안에서 업로드된 이미지 원본이지만, 공유 그룹에 직접 속하지 않는다.
- 사진과 공유집(앨범)의 소속 관계는 `shared_album_photo` 관계 테이블로 표현하는 N:M이며, 같은 사진을 여러 공유집(앨범)에 담을 수 있다.
- 사진은 항상 1개 이상의 공유집(앨범)에 속해야 한다. 사진의 소속 공유 그룹이 필요하면 `shared_album_photo`로 연결된 공유집(앨범)의 소속 공유 그룹을 조인해 구한다.
- 로컬 저장공간 또는 로컬 사진집에서 공유집(앨범)으로 사진을 불러오는 플로우는 사진 업로드로 처리한다.
- 공유 사진 또는 공유집(앨범)을 로컬 저장공간으로 복사하는 플로우는 다운로드이며 서버 엔티티를 새로 만들지 않는다.
- 사진을 다른 공유집(앨범)에 추가하거나 제거하려면 `shared_album_photo` 행을 추가·삭제한다.
- 사진 원본은 원칙적으로 업로더만 수정·삭제할 수 있고, 업로더가 탈퇴한 경우 삭제는 공유 그룹 방장이 할 수 있다.

## 7. 사진 좋아요와 댓글

- 사진 좋아요는 사용자가 특정 사진에 좋아요를 누른 상태이다.
- 한 사용자는 같은 사진에 좋아요를 한 번만 누를 수 있다.
- 좋아요 취소 시 `photo_like` 행을 물리 삭제한다.
- 사진 댓글은 단일 사진에 달리는 댓글이다.
- 사진 댓글 작성과 조회는 사진이 속한 공유 그룹 활성 멤버십을 요구한다.

## 8. 그룹 채팅 메시지

- 그룹 채팅 메시지는 공유 그룹 안에서 작성하는 일반 채팅 메시지이다.
- 사진 댓글과 별도 테이블인 `shared_group_chat_message`에 저장한다.
- 메시지 작성과 조회는 공유 그룹 활성 멤버십을 요구한다.
- MVP는 메시지 작성과 조회만 제공하며 수정·삭제는 후속 범위다.
- 1차 구현은 폴링 조회를 기준으로 한다.

## 9. 삭제 정책

- 사용자, 공유 그룹, 공유집(앨범), 사진은 soft delete한다. 촬영 기기명은 별도 엔티티가 아닌 사진 메타데이터이므로 삭제 대상이 아니다.
- 공유 그룹 멤버십과 사진 좋아요는 물리 삭제한다. MVP에는 사진 댓글과 그룹 채팅 메시지의 사용자 수정·삭제 API가 없다. 사진 댓글은 사진 물리 정리 시 삭제하고, 그룹 채팅 메시지는 공유 그룹 물리 삭제 시 FK cascade로 정리한다.
- 사용자 탈퇴 시 `app_user.display_name`은 "탈퇴한 사용자"로 갱신하고 `app_user` 행은 재가입 복구를 위해 물리 삭제하지 않는다.
- 사용자 탈퇴 시 사진 좋아요는 물리 삭제한다.
- 탈퇴한 사용자가 기존에 생성·작성·업로드한 공유 콘텐츠는 즉시 삭제하지 않고 사용자 표시는 "탈퇴한 사용자"로 대체한다.
- 개별 삭제한 공유집(앨범)·사진과 삭제된 공유 그룹 데이터는 30일 뒤 물리 삭제한다. 공유 그룹은 하위 공유집(앨범)·사진을 같은 시각에 soft delete하고, 사진 매핑으로 Object Storage 객체를 먼저 정리한 뒤 그룹과 초대 코드 예약을 삭제한다.
- Object Storage 객체 삭제가 실패하면 DB 행은 남겨 재시도한다.
- 공유 그룹 물리 삭제 시 해당 초대 코드 예약 원장 행도 삭제한다.

## 10. 다음 단계 연결

2단계 한글-영어 매핑에서는 위 용어를 기준으로 아래 영어 표준명을 확정한다.

```text
공유 그룹 -> shared_group
공유 그룹 멤버십 -> shared_group_membership
공유집(앨범) -> shared_album
사진 -> photo
사진 좋아요 -> photo_like
사진 댓글 -> photo_comment
그룹 채팅 메시지 -> shared_group_chat_message
```
